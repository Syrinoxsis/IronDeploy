IronDeploy · карта потоков данных

Откуда WinPE берёт данные?

Три источника участвуют в одной установке Windows, но каждый отвечает за свой тип данных и свой этап.

! WDS, SMB-шара и IronAPI — не три альтернативных способа установки. Это три параллельных канала: WDS загружает саму среду WinPE, шара отдаёт большие файлы, а API сообщает, что именно выбрать и как отслеживать установку.

Три источника → одна установка

Стрелки показывают, какие данные входят в WinPE, а затем переносятся в установленную Windows.

Канал №1 · загрузка

WDS / PXE

Даёт компьютеру стартовую среду, ещё до подключения шары и API.
  • Загрузочный образ boot.wim
  • Windows PE и нужные WinPE-компоненты
  • deploy.ps1, GUI и deployment engine
  • deploy.config.ps1 с адресами и учётными данными
  • Встроенный сертификат доверия IronAPI, если проверка TLS включена
Не отдаёт: устанавливаемый Windows WIM/ESD, драйверы и программы. В IronDeploy WDS нужен прежде всего для старта WinPE.
Канал №2 · файлы

SMB-шара

\\server\IronDeploy → временный диск Z:. Отдаёт тяжёлые байты напрямую.
  • Images: Windows .wim / .esd
  • Drivers: рекурсивные пакеты .inf
  • Unattend: шаблон ответа Windows Setup
  • PostInstall: SetupComplete.cmd и postinstall.ps1
  • Programs: выбранные .msi / .exe
Не решает: какой образ/индекс выбрать и какие программы разрешены. Шара хранит файлы; решение и метаданные приходят из API.
Канал №3 · управление

IronAPI

HTTP(S) + Bearer secret. Передаёт план, метаданные и состояние установки.
  • Предложение имени компьютера
  • Catalog: образы, индексы, готовность, программы, массивы аргументов, свойства MSI и SHA-256
  • Manifest: окончательно выбранный образ, индекс и программы
  • Начало установки, этапы, ошибки и финальный статус
  • ODJ: provision → blob → acknowledge
  • Флаги локальных администраторов для postinstall
Обычно не передаёт: большие WIM/ESD и установщики. Исключение — небольшой секретный ODJ blob, который всегда идёт через API, а не через SMB.

Postinstall

Работает уже в установленной Windows.

1Windows запускает SetupComplete.cmd
2Применяется политика локальных администраторов
3Повторно проверяется SHA-256 программ
4Устанавливаются выбранные MSI/EXE
5При включённой TLS-проверке сертификат добавляется в Windows Root store
↗Обратный канал в IronAPI: postinstall отправляет результат программ и переводит deployment в состояние completed. Если API недоступен, выполняются повторные попытки.

WDS = загрузить

Доставляет boot.wim и встроенную среду X:\IronDeploy. Используется до начала самой установки.

SMB = прочитать файлы

Хранит большие и статические payload-файлы. WinPE читает их с подключённого диска, не прокачивая через API.

API = решить и записать

Возвращает разрешённый каталог и финальный план, создаёт ODJ и сохраняет ход/результат deployment.
