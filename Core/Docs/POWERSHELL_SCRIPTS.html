Основные точки входа

Именно эти команды логично документировать для повседневной работы.

Запуск SetupWeb

Tools\Start-IronDeploySetupWeb.ps1
точка входа

Минимальный wrapper с устойчивым путём запуска из каталога Tools.

  • Передаёт TTL токена, TTL сессии и флаг установки зависимостей.
  • Всю работу делегирует launcher-скрипту в каталоге SetupWeb.
Изменяет
Ничего самостоятельно
Вызывает
SetupWeb\Start-IronDeploySetupWeb.ps1

Запуск IronAPI

Tools\Start-IronAPI.ps1
точка входа

Запускает рабочий IronAPI через Uvicorn.

  • Читает bind host, TCP port и access-log из Api\.env.
  • Проверяет Python virtual environment.
  • Создаёт Data, ODJ\pending и Logs.
  • Работает в foreground до Ctrl+C.
Изменяет
Может создать служебные каталоги
Запускает
uvicorn app.main:app

Сборка WinPE

Tools\Build-IronDeployWinPE.ps1
точка входа

Публичный wrapper для целей Wim, Iso и Both.

  • Маршрутизирует сборку в низкоуровневые build-скрипты.
  • Поддерживает initialization, mount recovery и PXE update.
  • Формирует SHA256SUMS и build-info с commit SHA.
Изменяет
.work, dist и опционально PXE bundle
Требует
Администратор и Windows ADK

Проверка установки

Tools\Test-IronDeploy.ps1
read-only

Общая диагностика без запуска API и без сборки WinPE.

  • Проверяет необходимые файлы, каталоги, WIM и SMB share.
  • Проверяет отсутствие широкого read-доступа к ODJ.
  • Парсит синтаксис всех PowerShell-файлов, включая Runtime.
Изменяет
Ничего
Exit code
1 при наличии ошибок, иначе 0

Настройка и конфигурация

Консольный мастер всей установки

Tools\ConfigureMaster.ps1
частично legacy

Исторически единая operator-facing точка настройки. Сейчас значительно пересекается с SetupWeb.

  • Создаёт структуру каталогов IronDeploy.
  • Готовит WinPE working tree через initializer.
  • Записывает deploy.config.ps1, включая SMB-пароль открытым текстом.
  • Создаёт локальный SMB share и назначает SMB/NTFS read-права.
  • Настраивает listener IronAPI, unattend и ACL каталога ODJ.
  • Вызывает подробный API setup, validation и WinPE build wrapper.
Параметры
-InitialSetup, -Validate
Записывает
Api\.env, WinPE\Runtime\deploy.config.ps1, рабочий unattend
Особенность
До сих пор предлагает Default Image Index и live DISM progress, удалённые из SetupWeb

Подробная настройка IronAPI

Api\Setup-IronAPI.ps1
CLI setup

Настраивает API-часть глубже, чем старый master.

  • Database URL, computer naming, LDAP и ODJ.
  • LDAP и djoin используют run-as identity процесса IronAPI.
  • Проверяет TCP LDAP, пути и identity.
  • Может перезапустить уже существующую службу IronAPI.
Параметры
-Validate, -InitialSetup, -ServiceName
Не делает
Не устанавливает службу и не запускает API в foreground

Настоящий launcher SetupWeb

SetupWeb\Start-IronDeploySetupWeb.ps1
внутренний

Подготавливает изолированное web-приложение и запускает его только на localhost.

  • Создаёт SetupWeb\.venv при отсутствии.
  • По умолчанию выполняет pip install requirements.
  • Выбирает случайный свободный порт.
  • Генерирует одноразовый bootstrap token и запускает Uvicorn.
Сеть
Только 127.0.0.1
Важно
IronAPI не запускает

Низкоуровневая сборка WinPE

Эти скрипты лучше вызывать через Build-IronDeployWinPE.ps1.

Initialize working tree

WinPE\Build\Initialize-IronDeployWinPE.ps1
внутренний
  • Создаёт .work\WinPE_amd64 через copype amd64.
  • Добавляет WMI, NetFX, Scripting, PowerShell, StorageWMI и DismCmdlets.
  • Добавляет en-us component packs.
  • Проверяет архитектуру и mount state.
Не делает
Не копирует Runtime и не публикует dist
Удаление
Только проверенный .work\WinPE_amd64 после подтверждения

Rebuild WIM

WinPE\Build\Rebuild-IronDeployWim.ps1
внутренний
  • Монтирует boot.wim index 1.
  • Копирует шесть файлов из WinPE\Runtime.
  • Удаляет устаревший IronDeploy.Console.ps1.
  • Проверяет каждую копию через SHA-256.
  • Публикует dist\IronDeploy_PE.wim.
Параметры
-UseExistingMount, -RecoverInvalidMount
ISO
Не создаёт и не изменяет

Rebuild ISO

WinPE\Build\Rebuild-IronDeployIso.ps1
внутренний
  • По умолчанию обновляет boot.wim текущим Runtime и публикует WIM.
  • Создаёт staged ISO через MakeWinPEMedia.
  • Атомарно заменяет финальный ISO и проверяет хеш.
  • С -SkipWimUpdate только упаковывает текущий working tree.
Параметры
-RecoverInvalidMount, -SkipWimUpdate
Публикует
IronDeploy_PE.iso и, без SkipWimUpdate, также IronDeploy_PE.wim

Обнаружено несоответствие Target Iso

Документация описывает -Target Iso как упаковку текущего working tree без изменения WIM. Фактически wrapper без -SkipWimUpdate монтирует и обновляет boot.wim, а ISO-скрипт публикует ещё и WIM. При этом build-info для Target Iso перечисляет только ISO. Код, документация и metadata сейчас расходятся.

Автоматический скрипт установленной Windows

Post-install

ServerTemplates\PostInstall\postinstall.ps1
автоматический

Запускается SetupComplete.cmd уже внутри установленной Windows, а не оператором на deployment-сервере.

  • Пишет журналы и сетевую диагностику в C:\IronDeploy.
  • Выполняет gpupdate при успешном входе машины в домен.
  • Применяет политику встроенного Administrator и setup local admin.
  • Читает deployment.json и уведомляет IronAPI о завершении.
  • Повторяет уведомление до 12 раз и сохраняет error marker при неудаче.
Запускается через
ServerTemplates\PostInstall\SetupComplete.cmd, загруженный через IronAPI
Работает на
Целевом развёрнутом компьютере

Вспомогательные инструменты

Безопасный preview WinPE GUI

Tools\Show-IronDeployGuiPreview.ps1
preview
  • Загружает XAML интерфейса и подставляет фиктивные данные.
  • Проигрывает сценарий фальшивого deployment progress.
  • Не загружает deployment engine, не подключает SMB и не трогает диски.
  • Кнопки reboot просто закрывают preview.
Требует
PowerShell STA и WPF
Риск
Косметический preview, destructive actions отсутствуют

Где обязанности пересекаются

SetupWeb

  • Api\.env
  • deploy.config.ps1
  • unattend settings
  • superadmin bootstrap

ConfigureMaster

  • Api\.env
  • deploy.config.ps1
  • unattend
  • SMB, ACL, WinPE orchestration

Setup-IronAPI

  • Api\.env
  • LDAP/ODJ run-as identity
  • API validation
  • service restart

Практический вывод

  1. SetupWeb логично сделать единственным UI для конфигурации.
  2. Setup-IronAPI.ps1 пока нужен для углублённой проверки identity и перезапуска службы.
  3. ConfigureMaster.ps1 полезен для SMB, ACL, directory layout и orchestration, но его конфигурационные формы уже дублируют SetupWeb.
  4. Build-IronDeployWinPE.ps1 должен оставаться единственной публичной точкой сборки.
  5. Поведение Target Iso следует синхронизировать с документацией и build-info.
  6. Повторяющуюся DISM/mount-логику WIM и ISO можно позднее вынести в общий внутренний модуль.
